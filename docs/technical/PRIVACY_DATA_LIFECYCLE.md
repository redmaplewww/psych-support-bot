# 隐私数据生命周期与注销范围

本文是产品协议、代码实现和运维动作之间的核对基线。用户界面展示的协议条款以 `domain/consents.py` 为单一文本源，实际目的地由 `/v1/users/privacy-agreement` 返回。

## 数据流

| 数据 | 来源 | 处理与目的地 | 服务端持久化 | 导出 | 注销 |
| --- | --- | --- | --- | --- | --- |
| 账号与认证 | 用户名登录、Apple/Google/Huawei OIDC、未来 Passkey | 本服务；OIDC 公钥从对应供应商 JWKS 获取 | 内部账号 ID、登录句柄、密码哈希、外部身份假名、Passkey 公钥、挑战和刷新会话；不保存 OIDC ID Token | 导出账号及非秘密身份元数据；不导出密码/令牌/挑战哈希、Passkey 公钥或供应商 subject | 同步删除 |
| 对话与派生数据 | 用户输入、模型回复 | 文本模型用于回复、风险识别、摘要和记忆 | 对话、消息、风险事件、摘要、切片、画像 | 全量导出 | 同步删除 |
| 画像记忆偏好 | 用户在“我”页选择 | 控制画像提取、注入、质询和行为时间画像 | 账户级开关；缺省为开启 | 随数据表导出 | 注销同步删除 |
| 测评、练习、打卡、计划、周报 | 用户操作及模型反馈 | 本服务；需要 AI 解读时发送必要内容到文本模型 | 对应业务表及练习会话 | 全量导出 | 同步删除 |
| 语音 | 麦克风、待朗读文本 | 音频发往 STT，待朗读文本发往 TTS | 不保存原始音频；转写文字按对话保存 | 转写文字随对话导出 | 转写文字随对话删除 |
| 产品分析副本 | 本轮用户输入、最终展示回复 | 本地去标识化后发送 Langfuse，用于质量、安全和性能分析 | Langfuse 保存；本地不另建内容副本 | 不包含在业务 JSON 导出 | 按假名标识异步删除 |
| 运行与商业化指标 | 请求及用户动作 | Langfuse 接收耗时、用量、失败标记；`usage_events` 保存动作元数据 | Langfuse 与业务库 | `usage_events` 随数据表导出 | 两处分别删除 |
| 应用运行日志 | 服务运行 | 技术状态、计数和固定错误类型；不主动写入内容、画像或原始用户标识 | 部署环境日志系统 | 不进入用户导出 | 按部署方日志保留期到期删除 |
| 客户端数据 | 登录、草稿、记录缓存 | 当前 Web/原生客户端 | Web Access Token 仅存页面内存，Refresh Token 为 HttpOnly Cookie；原生端 Refresh Token 交由 Keychain/Keystore 保存；`np_*`、`psb_assess_draft_*` 保存 Web 产品状态 | 不进入服务端导出 | 当前 Web 产品键和认证 Cookie 同步清理；原生端须清理安全存储，其他设备需分别退出 |

文本模型可能接收本轮原文、必要的近期历史、摘要、画像及相关记录。应用不承诺这些输入已匿名化。具体配置的主机和模型会在协议接口中展示；目的地变化会改变同意版本。

画像记忆关闭后，系统不再生成或使用画像信念，也不再维护行为时间画像；
当轮风险识别与危机处理继续运行。关闭本身不会删除既有画像，“关闭并清除
已有画像”会删除画像信念、事件、提取统计、干预事件和行为时间画像。

## Langfuse 去标识化

只有会话根追踪可以上传内容，范围固定为本轮用户输入和经过安全审查后最终展示的回复。内部 LLM 调用、系统提示词、历史上下文、摘要、画像以及任意结构化节点状态均由默认拒绝过滤器丢弃。

上传前，本地规则替换常见邮箱、手机号、身份证号、IP 地址、URL 和疑似凭据，并将文本限制为 4,000 个字符。原始用户 ID 和会话 ID 使用 `LANGFUSE_PSEUDONYM_KEY` 做 HMAC-SHA256 后截断，Langfuse 只收到 `anon_user_*` 和 `anon_session_*`。自由文本中的姓名、地点、事件组合仍可能使个人被识别，因此产品条款不得宣称无法重新识别或绝对匿名。

`LANGFUSE_CONTENT_ANALYTICS=false` 可关闭内容上传并保留运行指标。生产启用内容分析时，`LANGFUSE_PSEUDONYM_KEY` 必须稳定保存；密钥轮换会破坏旧追踪的按用户删除能力。

## 注销状态机

1. 注销接口先记录随机删除回执，以及删除所需的用户和会话标识。
2. 同一事务删除外部身份、Passkey、认证挑战、刷新会话、密码凭据、消息和用户数据清单中的每一张业务表，最后删除内部用户账号。
3. 后台任务同时以旧原始标识和新假名标识查询 Langfuse，只请求追踪核心字段，不下载内容。
4. Langfuse 接受批量删除后，任务进入 `verifying`，至少等待摄取宽限期并再次查询。仅在没有可关联追踪时标记 `linked_traces_deleted`，随后清空回执中的定位标识。
5. 用户通过 `/v1/privacy/deletions/{receipt}` 查询状态。供应商或网络失败只保存固定错误码，任务继续重试。

删除回执只证明在线业务库及可关联 Langfuse 追踪的处理状态。它不证明用户自行下载的文件、其他设备缓存、无法关联的旧追踪、离线备份或模型/语音供应商留存已经删除。

## 运维要求

- 部署前配置稳定且相互独立的 `JWT_SECRET_KEY`、`AUTH_IDENTITY_HASH_KEY` 和 `LANGFUSE_PSEUDONYM_KEY`，并把密钥纳入备份与轮换计划。
- Apple、Google、Huawei 的 client ID 必须按环境分别加入允许列表。不要接受客户端提供的 issuer、JWKS URL 或任意 audience。
- Passkey 仅在确定长期持有的 RP ID 和精确 HTTPS Origin 后启用；开发、测试、生产环境使用不同凭据。
- 保持 `LANGFUSE_DELETE_HISTORY=true`，除非已验证该环境从未上传过可关联内容。
- 监控长期停留在 `pending` 或 `verifying` 的回执，并人工处理 `langfuse_credentials_required`、`langfuse_cleanup_failed` 和无法关联的旧追踪。
- 对数据库备份设置明确保留期；从备份恢复前必须重放注销清单，避免已删除账号复活。
- 限制 Langfuse 项目访问权限和留存期，并在供应商合同中确认内容留存、训练用途与删除能力。
- 当前用户生命周期锁仅保证单进程部署中的注销与并发写入互斥。启用多 worker 或多实例前必须换成数据库或分布式锁。
