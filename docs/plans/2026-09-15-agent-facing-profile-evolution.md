# Agent 侧用户理解系统演进计划

状态：拟执行\
日期：2026-09-15\
范围：画像记忆、异步综合、Agent 接入、用户控制、导出与删除

## 1. 产品目标

画像的主要用途是帮助 Agent 在多轮和跨会话中更准确地理解用户，从而减少重复询问、维持关系连续性，并选择更合适的表达、知识和帮助方式。

画像不是面向用户的人格报告，也不承担帮助用户认识自己的主要职责。系统不得在普通产品界面中展示未确认、仍在形成、可能引发心理暗示或可能导致焦虑的推断，不得以“系统认为你是某种人”的方式描述用户。

用户对可关联到自己的画像数据拥有控制权：能够关闭画像处理、删除画像数据、撤回相关同意，并通过明确的个人信息访问/复制通道取得依法应提供的数据副本。

## 2. 非目标

- 不建立人格诊断、人格类型或精神疾病推断系统。
- 不把画像做成用户每日查看的“自我分析报告”。
- 不引入 Supervisor、CrewAI、AutoGen 或多 Agent 自由讨论平台。
- 不引入第二套长期记忆数据库作为画像事实源。
- 不让未验证假设直接决定干预、练习、风险判断或向用户作出断言。
- 不将画像用于广告、定价、用户价值分层或跨产品营销。

## 3. 已确认的产品决策

### 3.1 可见性

1. 普通“我”页面不展示画像推断、模式、假设或“对你的整体理解”。可以保留用户主动填写或已经明确确认的背景、偏好、目标和边界，统一放在“记忆与偏好”中，支持逐项修改和删除。
2. 页面保留“个性化记忆”开关、用途说明、数据类别说明、清除入口和个人信息副本入口。
3. 用户明确进入数据管理流程时，可以查看依法需要提供的存储事实和推断数据；该流程不是日常产品内容。
4. 待验证假设仅供系统内部校验，不得原样进入对用户可见的回复。
5. 用户明确表达的偏好和事实可以在纠错界面中按需呈现，但不将其包装成人格结论。

### 3.2 告知、导出与删除

1. 不把画像处理事实藏在小字、折叠到底部或含糊措辞中。首次开启时用简短、显著的说明告知用途、数据类别、保存方式和控制入口。
2. 将“内容与记录导出”和“个人信息副本”区分命名：
   - 内容与记录导出：用户创作的对话、练习、测评和打卡内容。
   - 个人信息副本：依法应提供的全部可关联数据，包括适用情况下的派生画像、处理状态和来源说明。
3. 若只提供一个名为“导出全部数据”的入口，它必须包含持久化的可关联画像与推断数据。
4. 关闭画像后立即停止提取、综合、检索、提示词注入和行为时间画像更新。
5. 清除画像时删除背景、belief、事件、提取统计、干预事件、时间画像、画像任务和画像快照；不得残留可继续影响 Agent 的副本。
6. 匿名化且无法再关联用户的聚合统计不进入用户副本；可通过密钥或映射重新关联的数据仍按可关联数据处理。
7. 医疗健康、宗教信仰、创伤、物质使用等敏感类别默认不做长期保存；确有产品必要时增加单独、明确的同意和字段级删除。

发布前由目标市场的专业法律顾问复核个人信息副本范围、敏感信息同意、自动化决策告知以及供应商跨境处理安排。

### 3.3 执行方式

1. Celery 不是第一阶段的必要依赖。先复用现有 `privacy_deletion` 模式，以数据库任务表、FastAPI lifespan 后台轮询器和 `asyncio.to_thread` 实现可重试异步任务。
2. 当服务扩展到多个实例、画像任务需要独立扩缩容或数据库轮询成为瓶颈时，再将同一任务处理函数接入已有 Celery/Redis；业务状态和幂等语义保持不变。
3. K1 确定性提取保持同步，和用户消息、练习完成事实及显式偏好一起落库，为异步任务提供一致的证据水位。
4. K2 的 LLM 语义提取移出用户请求链路，交给异步画像任务。用户明确确认、否决、编辑和关闭画像的状态变更保持同步立即生效。
5. K3 综合全部异步执行，不再挂在新一轮用户请求触发的切片收尾路径上。

## 4. 最小技术架构

沿用现有在线 Conversation Graph 和 SQLAlchemy。新增一个小型异步 LangGraph，由应用内持久后台 Worker 执行；Celery/Redis 作为规模化替换层，不作为首版运行前提。不新增 Agent 平台。

```text
在线对话完成
  -> 保存消息、belief 和用户明确事实
  -> 写入/合并 profile_evolution_jobs
  -> 应用内持久后台 Worker 领取任务
  -> 异步 ProfileEvolutionGraph
       1. load_evidence      读取新增证据
       2. formulate          一次 LLM 调用生成候选理解
       3. validate           代码校验证据、敏感性与生效资格
       4. compile_policy     生成 Agent 可消费的支持策略
       5. persist_snapshot   保存版本化快照
  -> 下一轮只读取最近一个 active 快照
```

第一阶段不启用 LangGraph Store。业务数据库继续作为画像、导出和删除的唯一事实源。第一阶段也不要求 LangGraph checkpointer；任务表、幂等键和应用内 Worker 重试足以恢复。只有在需要节点级恢复、人工中断或执行重放时再增加持久化 checkpointer。

首版 Worker 与现有 `services/privacy_deletion.py::deletion_worker` 同构。禁止只使用 FastAPI `BackgroundTasks` 或裸 `asyncio.create_task` 承载画像写入；进程退出后仍须能从数据库任务表恢复。多实例部署时，任务领取必须使用数据库锁、租约或迁移到 Celery，避免两个实例同时处理同一用户。

## 5. 数据契约

### 5.1 Agent 可读取内容

在线 Agent 只能读取：

- 用户明确表达且仍有效的低敏感事实；
- 用户明确表达的沟通偏好和边界；
- 已确认或达到稳定证据门槛的模式；
- 经确定性编译的 `support_policy`；
- 近期生活事件及其有效期；
- 已验证有效或不适合的练习反馈。

### 5.2 Agent 不可读取内容

- 原始内部推理过程；
- 未通过证据校验的候选画像；
- 单轮行为信号直接形成的人格解释；
- 被用户否决或已过期的理解；
- 未取得相应同意的敏感背景；
- 用于形成画像的第三方个人信息。

### 5.3 待验证假设的使用

待验证假设保存在内部候选快照中，不直接进入回复提示词。系统如需进一步了解，只向提问规划器提供不带结论的 `information_gap`，例如“尚不了解工作评价带来的具体压力来源”，而不是“用户可能害怕被否定”。每轮最多使用一个信息缺口，并受 `no_question_mode`、危机模式和用户边界约束。

### 5.4 语音信号

语音信号属于短期、低权重的 `behavioral_observation`，不是身份事实、人格特征或稳定画像。规则如下：

- 原始录音不进入画像证据库；画像层只接收 VAD 产生的停顿次数、有效语音时长等最小化元数据。
- 单次停顿、短句、回复延迟和深夜使用仅在当前会话内帮助调整节奏，不能单独形成 belief、候选解释或支持策略。
- 回复延迟必须标记数据质量；应用退到后台、网络中断或跨设备继续时不得解释为犹豫。
- 只有同类信号跨多个会话重复，且有文本证据或用户明确表达支持时，才可作为某个观察的辅助证据。
- 持久化时保存离散类别和证据会话，不保存精确录音时间线；默认设置较短有效期，到期后不参与画像综合。
- 语音信号不得用于危机降级、诊断、人格判断或推断用户“不愿意聊”。向用户提问时使用中性措辞，不暴露系统做出的行为解释。

### 5.5 最小新增表

新增 `profile_evolution_jobs`：

- `id`
- `user_id`
- `evidence_watermark`
- `prompt_version`
- `idempotency_key`
- `status`
- `attempt_count`
- `error_code`
- `created_at` / `started_at` / `completed_at`

新增 `profile_snapshots`：

- `id`
- `user_id`
- `version`
- `status`：`shadow` / `active` / `retired`
- `content_json`
- `support_policy_json`
- `evidence_watermark`
- `prompt_version`
- `created_at`

继续使用 `ProfileBelief` 和 `ProfileBeliefEvent` 保存观察与证据事件。为其补充或派生：证据主体、敏感类别、不同会话数、不同情境数、有效期和最近证据时间。暂不拆分成大量心理学实体表。

## 6. 工作单元

### 工作单元 A：兑现现有隐私与运行承诺

变更：

- 修复 `SliceSummary.summary` 与 `summary_text` 字段不一致。
- 关闭画像时禁止 `understanding_json`、背景、belief、画像检索和画像提问进入下一轮。
- 清除画像时清空 `UserProfile.background_json`、`understanding_json` 以及新增快照和任务。
- `has_profile_memory_data` 纳入所有画像承载位置。
- 为背景提取增加用户/第三方/不确定主体识别。
- 修复支持证据到来后不刷新 `last_evidence_at` 的问题。
- 质询候选实现真正的不同会话证据门槛。

验收：

- 关闭后任何画像内容都不进入 Agent 输入。
- 清除后数据库、缓存、任务队列和提示词中均无画像残留。
- 重复清除安全且幂等。
- 未确认的第三方事实不会成为用户背景。

### 工作单元 B：调整用户界面与协议

变更：

- 将“个人画像”“对你的理解”改为“个性化记忆”。
- 删除普通页面上的画像卡片、熟悉程度头像和综合理解内容。
- 保留用途说明、开关、清除、数据类别和个人信息副本入口。
- 更新隐私协议：说明系统会从对话和记录中形成内部个性化理解，用于调整回复，不用于诊断和广告。
- 对敏感背景建立单独同意；未同意时只允许当轮处理并在当轮结束后丢弃。
- 明确 Langfuse 只接收协议允许的去标识化当轮输入和最终输出，不上传画像、历史、摘要和内部假设。

验收：

- 普通页面不展示任何推断性画像内容。
- 开启前能够看见清晰、简短的用途说明。
- 用户可以在不关闭账号的情况下停止和清除画像。
- “内容与记录导出”与“个人信息副本”不会被误认为同一范围。

### 工作单元 C：建立轻量异步画像工作流

变更：

- 增加应用内 `profile_evolution_worker`，复用现有持久删除 Worker 的启动、停止和轮询模式。
- 增加按用户合并任务、幂等键和单用户互斥。
- 建立 `ProfileEvolutionGraph` 五节点流程。
- 将 K2 LLM 语义提取和 K3 综合迁入 Worker；K1 和用户显式状态更新保留同步。
- 不再依赖切片关闭作为唯一综合触发条件。
- 触发条件包括：新增有效证据达到水位、用户确认/否决、身份事实变化、练习反馈变化、出现反证、每天最多一次兜底综合。
- 任务失败只记录固定错误码，不保存模型原始错误正文。
- 预留同一处理函数的 Celery task 包装；达到多实例或独立扩缩容条件后切换，不改变任务表和画像数据契约。

验收：

- 异步综合不增加在线回复延迟。
- 同一证据水位重复任务只产生一个快照。
- Worker 重启后可以安全重试。
- 一个用户的任务不会并发覆盖画像版本。
- 画像关闭时队列中的未执行任务安全退出且不写入。
- 进程在任务中途退出后，租约过期的任务能够由下一次启动恢复。

### 工作单元 D：候选理解与确定性校验

`formulate` 一次输出：

- 可观察模式；
- 证据 ID；
- 支持证据与反证；
- 两个以内的候选解释；
- 信息缺口；
- 已观察到的有效帮助方式；
- 候选支持策略。

`validate` 强制执行：

- 所有观察必须引用存在且属于该用户的证据；
- 不同消息不等于不同会话，稳定模式必须满足不同会话门槛；
- 单轮停顿、回复延迟和深夜使用不能独立形成稳定解释；
- 语音行为信号只能作为辅助证据，不能独立提高模式到 active；
- 禁止诊断、人格障碍、依恋类型和认知歪曲人格化标签；
- 禁止把第三方事实归到用户；
- 禁止未同意的敏感信息进入持久快照；
- 有反证时不得输出确定性结论；
- 模型自报置信度不直接决定生效。

验收：

- 伪造或越权证据 ID 的结果被拒绝。
- 含诊断和人格盖章的结果被拒绝。
- 仅有单会话证据的模式保持 `shadow`。
- 用户否决后相同语义不能通过换措辞重新生效。

### 工作单元 E：编译 Agent 支持策略

将稳定理解编译为有限指令，不把原始画像塞进主提示词：

```json
{
  "response_length": "brief",
  "pacing": "validate_before_suggestions",
  "question_budget": 1,
  "avoid_topics": [],
  "preferred_knowledge_paths": ["act"],
  "exercise_constraints": ["do_not_repeat_breathing_offer"]
}
```

规则：

- 支持策略只能使用受控枚举和短文本参数。
- 风险判断始终独立于画像。
- 画像不能降低危机响应级别。
- 未验证假设不能改变练习、干预强度或知识学派。
- 用户明确偏好和否决优先于模型推断。

验收：

- 主提示词不包含 `why_possibly`、原始内部假设或画像分析正文。
- 同一快照产生确定且可测试的支持策略。
- 删除或关闭画像后自动回到默认策略。

### 工作单元 F：影子评估与分阶段发布

阶段：

1. 本地和 CI：结构、隐私、删除、幂等、主体归属和红线测试。
2. 影子模式：生成 `shadow` 快照，不影响回复。
3. 内部评审：抽检跨会话证据、反证处理和敏感内容。
4. 小流量：只开放回答长短、减少重复提问和用户明确偏好。
5. 扩大流量：开放稳定画像对知识检索的有限影响。
6. 最后评估是否允许稳定画像影响练习推荐。

任一阶段出现画像关闭失效、删除残留、人格盖章、主体误判或危机链路受影响，立即关闭画像生效开关并回退默认策略。

## 7. 衡量指标与继续投资条件

必须监控：

- 画像候选通过确定性校验的比例；
- 人工评审的证据支持率；
- 用户明确纠正、否决和清除比例；
- 重复提问率；
- 个性化开启与关闭组的帮助感、次日和七日留存差异；
- 单活跃用户画像调用次数与成本；
- 任务失败、重试和积压；
- 关闭、清除和个人信息副本生成成功率；
- 画像导致的不当断言、敏感信息误存和安全事件。

只有在影子评估证明候选理解质量可接受，且小流量实验显示帮助感或留存得到稳定改善时，才继续拆分第二个 LLM 质疑节点。若一次综合调用已经满足效果，不增加 Agent 数量。

## 9. 完成标准

本计划完成时应满足：

1. Agent 能从版本化、受控的支持策略获得个性化信息。
2. 普通用户界面不展示推断性画像或形成期假设。
3. 用户能够清楚知道画像处理存在，并能关闭、删除和依法取得个人信息副本。
4. 未确认画像不能以断言、练习选择或干预强度的形式影响用户。
5. 画像任务完全异步、幂等、可观测，不增加在线对话延迟。
6. 数据删除、导出、敏感同意和 Langfuse 范围与实际数据流一致。
7. 画像功能可以通过单一生效开关回退到无画像的默认支持体验。
